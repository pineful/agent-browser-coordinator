# 制限と今後の課題

時間枠は待機者がいる場合の次の begin における協調的な譲渡要求であり、強制タイムアウトではありません。実行中または結果不明の呼び出しは、確定した結果か検証済みの復旧まで所有権を保持します。keep-alive は手動の生存記録で、進行証明や lease 更新ではありません。`classify_work` はアダプターの主張を検証せず、並列候補も実際の並列 UI 実行を有効にしません。参加するラッパー外の直接呼び出しは遮断しません。

- 協力が前提です。直接ブラウザー呼び出しの遮断、actor 認証、ブラウザー読み取り専用の強制、外部呼び出しのキャンセルはできません。
- 一つの物理的ローカル DB で一つのリソースを扱います。コピー、別コンテナーの同じパス、NFS、複数の arbiter はサポートモデル外です。
- 安定版 0.3.5 に daemon、正確な時刻のスケジューラー、自動メッセージ、所有者への自動問い合わせ、timeout 自動回収はありません。期限は実呼び出しの終了証拠ではなく、作業内容の進展も汎用の生存証明ではありません。
- status、タブ記録、保存スクリーンショットは時点の観察です。API の部分タブ一覧を全体とみなしません。未保存内容の保持、アップロード、公開成功を代わりに証明しません。
- ソース配布に DB、cookie、認証情報、セッションは含みません。復元テストはソフトウェアを検証し、実サービス状態や特定サイトを保証しません。
- 全共有 UI の直列化は保守的な現行方針です。環境によってタブ別 DOM/API の並列化が可能でも、その独立性はまだ未検証です。このパッケージで運用の全体所有権ルールを緩めません。

## ロードマップであり現行機能ではない

実ワーカーの寿命・キャンセルに結びついた認証済み問い合わせ/keepalive、有限 timeout、遅れて復帰したワーカーの fencing、未解決呼び出しの観察専用復旧を研究します。v0.4 候補は完成したホスト watchdog ではなく、今回の安定配布には含めません。

タブ単位操作と全体の画面、キーボード/マウス、native ファイル選択、ページ modal の独立性は別途検証予定です。競合・中断・再起動試験なしで並列化や無競合を保証しません。
