# エージェントにインストールを依頼するプロンプト

以下をコピーして利用するエージェントに渡してください。最初の範囲は隔離したインストールと検証です。二つ目は結果を確認した後、実際の接続先を指定して別途依頼する例です。必要な機能をエージェントとホストが提供している必要があります。プロンプト自体が権限や成功を保証するものではありません。

二つのハッシュ欄には、このリリースの信頼できるSHA256SUMS記録で確認した64桁を入力してください。値がない場合や配布元を確認できない場合は実行せず確認が必要です。ZIP自身の最終ハッシュをZIP内の文書に埋め込むことはできないため、別のリリース検証記録を使います。

## 1. インストールと検証のみを依頼する

```text
Agent Browser Coordinator 0.3.5をインストールして検証してください。
リポジトリ: https://github.com/pineful/agent-browser-coordinator
対象リリース: https://github.com/pineful/agent-browser-coordinator/releases/tag/v0.3.5

最初にホストOS、Pythonバージョン、現在のファイル書き込み・ネットワーク・ソフトウェア実行権限を確認してください。ローカル検証環境はPOSIX/Python 3.12、パッケージの宣言はPython >=3.10です。他の環境は実際の対応を確認し、未検証の互換性を明示してください。この依頼を別のコンピューターへのアクセスや権限拡大の許可と解釈しないでください。

既存のcoordinatorコード、DB、ブラウザーセッションを確認して保持してください。新しい専用フォルダーと別の仮想環境を使ってください。タグのインストール文書、LICENSE、NOTICE、SECURITY、制限・復旧文書を先に読んでください。mainは変更されるため、同じバージョン表示だけを根拠に別のソースを実行しないでください。

次のリリースファイルを取得し、実行・インストール・展開の前にSHA-256を確認してください。
agent-browser-coordinator-0.3.5-source.zip
<TRUSTED_SOURCE_ZIP_SHA256>
agent_browser_coordinator-0.3.5-py3-none-any.whl
<TRUSTED_WHEEL_SHA256>
ハッシュのプレースホルダーが残る場合は実行せず、確認済みの値を依頼してください。

このプロンプトの受領経路とリリース元の信頼性も確認してください。ダウンロードと一緒に取得したchecksumやmanifestだけでは真正性の証明になりません。ハッシュ不一致や信頼できない配布元の場合は実行を止めて報告してください。シンボリックリンク、パストラバーサル、既存ファイルの上書きを拒否し、新しいフォルダーにだけソースを復元してください。

検証したソース用に独立したツール用仮想環境を作り、宣言されたビルド依存だけを公式パッケージレジストリから必要な範囲で取得してください。信頼できる親フォルダーの下にまだ存在しない出力先を選び、python -m scripts.release_gate --output-dir <新しい出力先>を実行してください。セキュリティ回帰、合成状態の所有・復旧、許可ファイル一覧、成果物、新規インストール、ソース復元を検証するコマンドです。全段階のexit 0と成功レポートを確認してから合格と記録してください。テストの省略や失敗条件の緩和はしないでください。

次に、ハッシュが一致したリリースwheelを別の実行用仮想環境に--no-index --no-depsでインストールしてください。ソースツリーの外でバージョン、import、CLI、合成acquire/begin/end/releaseを確認し、欠落したDBが自動作成されないことも確認してください。検査用DBは一時的な合成状態のみです。

実運用DBの初期化、既存作業者の停止、ブラウザー操作、外部への公開・アップロード、自動実行サービスの設定は今回の範囲外です。認証情報、秘密の環境変数、セッション、トークンを出力したりリポジトリに保存したりしないでください。資格情報の新規作成、認証スコープの拡大、セキュリティ設定変更を自動で行わないでください。

最後に実際の環境、確認したバージョンとハッシュ、インストール場所、検査結果、未完了・未検証事項、接続の前提条件を報告してください。取得だけ、またはテストが実行できない状態を、インストール成功や運用準備完了と表現しないでください。既存環境が自動更新されたとも言わないでください。
```

## 2. 検証後に実際の接続を別途依頼する

ホスト、共有資源、作業者と実際のラッパー、許可する観察を指定してください。空欄が残る場合は、推測で運用を始めず確認が必要です。

```text
検証済みのAgent Browser Coordinator 0.3.5を次の環境へ接続する計画と検証を行ってください。
ホストと共有UI資源: <指定>
参加作業者と実際のツールラッパー: <指定>
全参加者が使う単一の絶対DBパス: <指定>
検証で許可する読み取り専用UI観察: <指定>

全参加者が同じDBパスを実際に読み書きできることを確認してください。既存コード、DB、owner、未解決の呼び出し、未保存の画面を確認してください。実運用初期化の前には、既存参加者の未解決呼び出しがなく、安全に停止または引き継いだ根拠が必要です。確認できなければ新しいDBで迂回したり状態を上書きしたりせず、阻害要因を報告してください。ソース復元と運用状態の再構成は別です。

実際にツールを呼び出す全ラッパーを、acquire → 現owner/token確認 → begin → 正確に一つのツール呼び出し → endと安全なrelease/handoffに接続して検証してください。失敗と未解決・結果不明を区別し、古いトークン、重複要求、中断後の再開を合成状態で検査してください。共有資源を取得し、画面と対象を新しく確認してから、上記で許可した読み取り専用観察だけを行ってください。他の作業者の未保存エディターやファイル選択画面を勝手に閉じないでください。

CLIの成功だけで実際のUI接続成功とは判断しないでください。接続したラッパー、実呼び出しとend記録の対応、安全な返却の根拠を報告してください。本ツールは協調型であり、認証境界でも直接UI呼び出しの強制遮断でもありません。自動ownerメッセージ/keepaliveやタブ並列実行は配布機能に含まれません。所有権の取得は外部公開・送信の許可ではありません。秘密情報は出力しないでください。
```
