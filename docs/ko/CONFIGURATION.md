# 공통 자원 설정

화면·포커스·키보드·마우스·native 선택창을 공유하는 브라우저처럼 자원 경계를 정합니다. 모든 참여자는 같은 물리적 로컬 SQLite DB를 사용해야 합니다. 다른 컨테이너에서 같은 경로가 보이거나 DB를 복사한 것은 공통성을 뜻하지 않습니다. 활성화 전에 작업자별 읽기·쓰기 가시성을 확인하고 NFS·네트워크 드라이브·동기화 폴더는 사용하지 않습니다.

다음은 신규 자원의 예시입니다. 부모 디렉터리가 먼저 있어야 합니다. `ABC_DB`는 shell 변수일 뿐 프로그램이 자동으로 읽지 않으므로 각 호출의 `--db`로 전달합니다.

```sh
mkdir -p -m 700 runtime
ABC_DB="$(pwd -P)/runtime/example-ui.db"
agent-browser-coordinator --db "$ABC_DB" init   --args '{"resource":"example-ui","confirmed_idle":true}'
agent-browser-coordinator --db "$ABC_DB" status
```

init은 새 자원에서 한 번만 실행합니다. 이전 작업자의 향후 제출 중단과 이미 제출한 모든 도구 호출 종료를 외부에서 확인한 뒤에만 `confirmed_idle=true`라고 선언할 수 있습니다. 이 값은 프로그램이 검증하는 사실이 아닙니다. 기존 DB는 덮어쓰지 않습니다. 누락·손상 시 각자 새 DB를 만들지 말고 [복구](RECOVERY.md)를 따릅니다.

작업자마다 고유한 actor를 주고 새 명령마다 새 request ID, 각 실제 호출마다 재사용하지 않는 action ID를 만듭니다. actor/tab/checkpoint/evidence는 영문자·숫자·`_ . : / -`의 1~120자 식별자입니다. URL·비공개 내용·비밀값을 넣지 않습니다. 식별자는 인증 수단이 아닙니다.

priority는 0~100, lease는 10~3600초입니다. 안정 코어의 연속 점유 상한은 1800초이며 다른 작업자가 120초 이상 기다렸거나 유효 우선순위가 높으면 다음 안전 경계에서 양도를 요구합니다. 실행 중 호출을 강제로 취소하는 시간 제한이 아닙니다. 다른 머신은 별도로 구현한 신뢰 가능한 부모 중계를 사용해야 하며 이 패키지에는 원격 서버가 없습니다.

## 0.3.4 파일·입력 검사

symlink가 없는 물리 경로와 그룹/다른 사용자가 쓸 수 없는 운영 부모 폴더를 사용합니다. DB는 hard link 별칭이 없는 일반 파일이어야 합니다. 기존 dashboard는 덮어쓰지 않으므로 새 스냅샷 파일명을 정합니다. JSON은 중복 키·비유한 숫자·문서에 없는 인자를 거절하며 읽기 명령은 인자 payload를 받지 않습니다. 이 검사는 작업자 신원 인증이 아닙니다.
